# webview — 화면

에이전트도 core 의 동작도 모른다. 확장과는 `protocol.ts` 의 메시지로만 말한다(`post` ↔
`main.ts` 의 받기). esbuild 가 `main.ts` 에서 시작해 한 파일(`dist/webview.js`)로 묶는다.

## 모양 — 창 공통 · 창 별

```
main.ts              진입점 — 이벤트 연결 · 확장에서 오는 것 · 키보드 · 부팅
common/              창 공통 — 어느 창도 모른다
  state.ts           같이 쓰는 상태(S) · post · boot · 설정 캐시 · 에이전트 조회
  screens.ts         화면 전환 (go · push · back)
  dom.ts             el · icon · 색 고르기
  markdown.ts        마크다운 그리기
  modal.ts · text.ts 모달 · 자잘한 글 도우미

list/                목록 · 검색
new/                 방 만들기
join/                붙는 화면 · 고치기 화면 (못 붙음 · 모델 없어짐)
setup/               에이전트 설정 · 로그인
chat/                채팅 — 뼈대 · 입력창(칩) · 말풍선 목록 · 말풍선 하나 · 첨부 ·
                     물어보는 카드 · 머리 메뉴 · 방 안 찾기 · 분기 · 스크롤
perm/                권한 시트
drawer/              참여자 서랍 · 대기 · 초대
```

**창 공통은 창을 모른다** — `common/` 이 창 모듈을 import 하면 린트가 막는다(형만 허용).
창끼리는 서로 부른다(채팅이 서랍을 닫고, 서랍이 채팅을 다시 그린다) — 화면이 그렇게
엮여 있어서다.

## 같이 쓰는 상태 — `S`

ES 모듈은 남의 `let` 을 다시 대입할 수 없다. 그래서 **둘 이상의 모듈이 읽거나 바꾸는
상태**는 `common/state.ts` 의 `S` 객체에 칸으로 둔다(`S.room` · `S.chat` · `S.stack` …).
한 모듈 안에서만 쓰는 것은 그 모듈의 `let` 으로 남긴다.

## 🔴 읽는 순간 도는 코드

**최상위에서 바로 도는 문장은 `main.ts` 에만 둔다.** 다른 모듈은 선언뿐이어야 어떤
차례로 읽혀도 같다. 그리고 `common/state.ts` 는 **잎**이다 — 값으로는 아무 webview
모듈도 import 하지 않으므로 늘 맨 먼저 읽힌다. 모듈 수준 초기값이 함수를 불러야 하면
(`let draftBots = [newDraftBot()]`) 그 함수가 닿는 것은 같은 모듈과 `state` 뿐이어야 한다.

나눌 때 이걸 어겨서 실제로 깨졌다 — `state` 가 채팅을 import 하던 시절, 방 만들기
모듈이 `boot` 가 아직 없는 순간에 읽혔다(화면 검사 26개가 한꺼번에 빨개졌다).
