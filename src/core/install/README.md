# 에이전트를 우리 자리에 둔다

> 2026-10-01 에 정했다. 사용자: *"우리 자리를 만들어 넣으면 이 모든게
> 가능한가"* → *"시행할 것"*.

## 왜

지금은 방을 열 때마다 `npx -y <꾸러미>` 를 띄운다. npx 가 알아서 받아주니
편한데, **받아둔 자리가 우리 것이 아니다.** 그래서 하고 싶은 일이 줄줄이
막혔다 (전부 2026-10-01 실측):

| 하고 싶은 것 | npx 로는 | 왜 |
|---|---|---|
| 품은 `claude.exe` 를 부르기 | ❌ | 자리가 `_npx/<해시>` 다. npm 내부 구조라 못 박는다 |
| 옛 판 지우기 | ⚠️ | **남의 자리다.** Zed·JetBrains 도 같은 꾸러미를 같은 폴더에 받는다 |
| 엔진 판 정확히 박기 | △ | `-p` 를 둘 줘서 되긴 하는데 꼼수다. `overrides` 가 정식이다 |
| 사용자가 고른 것만 받기 | ❌ | 받는 시점이 «처음 쓸 때» 라 우리가 못 고른다 |
| 받는 동안 진행률 보여주기 | ❌ | npx 안에서 일어나는 일이다 |

쌓인 값도 실물로 있다 — 이 기계에 **15자리 3.7GB**, 자리당 277~445MB.
한 번 받으면 아무도 안 지운다.

## 어디에

```
<globalStorageUri>/agents/<에이전트id>/
  package.json          ← 우리가 쓴다. overrides 가 여기 들어간다
  node_modules/
    .bin/<bin이름>      ← 어댑터를 띄우는 자리
```

`globalStorageUri` 는 이미 방 저장에 쓰는 자리다(`extension.ts`). **우리
것이므로 마음대로 지운다** — 이게 전환의 핵심이다.

## 받는 길이 둘이다

2026-10-06 에 Antigravity 를 들이면서 갈렸다. **어디에 두느냐는 같고**
받아오는 방식만 다르다.

```
npm 꼴 (Claude · Codex)          zip 꼴 (Antigravity)
<자리>/package.json              <자리>/agy_acp_server.exe
<자리>/node_modules/.bin/<이름>   <자리>/aio-installed.json   ← 무엇을 받았나
```

| | npm 꼴 | zip 꼴 |
|---|---|---|
| 적는 곳 | `pkg.spec` · `pkg.bin` | `pkg.binary[플랫폼]` |
| 받는 법 | `npm install --prefix` | `fetch` → `unzip.ts` |
| 판을 가리는 법 | `node_modules/…/package.json` | 받아둔 주소를 적어둔 표 |
| 엔진 박기 | `overrides` | 주소에 판이 들어 있다 |

🔴 **푸는 것은 바깥 도구에 안 기댄다.** `tar` 는 윈도우(bsdtar)에선 zip 을
풀지만 **GNU tar 는 못 풀고**, `unzip` 도 리눅스에 늘 있지 않다. 기계마다
있는 것이 달라서, 없으면 **설치가 통째로 막힌다.** `zlib` 으로 직접 읽는다.

⚠️ **zip-slip 을 막는다.** 압축파일 속 이름은 남이 정한 것이라 `../../` 가
들어 있을 수 있다 — 나온 경로가 목적지 안인지 매번 확인한다
(`tests/unzip.mts` 가 그 자리를 직접 때린다).

⚠️ **받는 것과 그 안에 든 것은 다르다.** 셋 다 우리가 받지만, npm 꼴은
안에 **진짜 CLI**(`claude.exe`·`codex.exe`)가 들어 있어 `auth login` 을
부를 수 있고, Antigravity 의 zip 에는 **ACP 서버뿐**이라 로그인이
`authenticate` 로만 된다. 자세한 건 `PIN.md` §G4.

★ **그래서 한 에이전트가 둘을 받기도 한다** (`pkg.extras`). Antigravity 가
그렇다 — 방을 돌리는 `agy_acp_server`(124MB)와 **로그인하는 `agy`**(181MB)가
따로 나온다. 둘 다 받아야 쓸 수 있고, 하나라도 못 받으면 **표를 안 쓴다** —
방은 돌아가는데 로그인할 길이 없는 상태를 «받아졌다» 고 하면 사용자는
막다른 길을 걷게 된다.

★ **`extras` 는 해시를 맞춰본다.** 매니페스트가 `url` 과 `sha512` 를 주므로
받은 것이 온전한지 안다 — ACP 레지스트리의 `binary` 는 그걸 안 준다.
끝의 끜리도 주소를 따라간다 — `agy` 로 써놓으면 윈도우에선 안 돌아간다
(`agy.exe` 여야 한다). 한 번 밟은 자리다.

⏪ **처음엔 매니페스트 주소를 가리켰다가 물렀다** (2026-10-06). 그 주소엔
**판이 없어** 늘 최신을 돌려준다 — ACP 서버는 1.3.0 에 박혀 있는데 CLI 만
혼자 올라가는, **한 제품의 두 조각이 어긋나는** 꼴이다. 매니페스트가 주는
주소와 해시를 그때 받아 **카탈로그에 박았다.** 올릴 때는 두 줄을 같이 고친다.

⚠️ **지우기는 떠 있으면 막힌다.** 윈도우는 돌고 있는 실행파일을 못
지운다 — 지우기 전에 연결을 내리고(`dropConnection` → `killTree`),
그래도 안 되면 몇 번 기다렸다 **못 지웠다고 말한다.** 반만 지운 자리를
«지웠다» 고 하면 다음에 «받아져 있다» 고 잘못 읽는다.


## 🔴 새 에이전트를 더할 때 — **채워야 하는 칸** (P6)

> 사용자: *"기능을 추가하거나 관리할게 추가될때 모든 에이전트에 대해 점검해야
> 된다는 거였어"* · *"에이전트 추가할때마다 저 것들을 따라서 추가해야될거고"*

**«우리가 관리하는 것» 하나하나에 대해, 그 에이전트는 어떻게 하는지를 적는다.**
빈칸으로 두면 **조용히 빠진다** — 빠진 줄은 아무도 못 본다. 안 되는 칸은
**«안 된다»가 답**이고, 그러면 화면이 그걸 말해야 한다.

| 관리하는 것 | 칸 | Claude | Codex | Antigravity |
|---|---|---|---|---|
| 받기 | `spec` / `binary` | npm | npm | **zip** (플랫폼별) |
| 엔진 판 누르기 | `overrides` | — | `@openai/codex` | — |
| 엔진 가리키기 | `exeEnv` | — (품은 exe 가 기본) | 🔴 `CODEX_PATH` | — |
| 로그인 하기 | `auth.login` / `auth.acp` | 터미널 | 터미널 | **ACP `authenticate`** |
| 로그아웃 | `auth.logout` / `auth.acp` | 터미널 | 터미널 | **ACP** |
| 로그인됐나 — 짐작 | `auth.file` | `.claude/.credentials.json` | `.codex/auth.json` | `.gemini/antigravity-acp/acp_token.json` |
| 로그인됐나 — 물어보기 | `auth.status` | `auth status` | `login status` 🔴 **stderr** | **없다** → 파일만 본다 |
| 세션 지우기 | `purge` | — (ACP 로 충분) | 🔴 `delete --force` (sqlite 가 남는다) | — |
| 남는 파일 치우기 | `purgeFiles` | — | — | 🔴 집 아래를 우리가 지운다 |
| 브라우저 조작 | `browser` (`AgentDef`) | ✅ `--chrome` (Claude in Chrome) | — (길이 없다) | — (안에 있어 보이나 **켜는 길을 아직 못 찾았다**) |

**칸마다 걸렸던 것**(왜 빈칸으로 두면 안 되는지):

```
exeEnv       안 박으면 사용자 기계의 codex 가 걸린다 — 오류도 안 나고 딴 판이 돈다
auth.status  Antigravity 는 없다. 「없음」이라고 **적었기에** 화면이
             «파일로만 확인» 이라고 말할 수 있다 — 빼버렸으면 아무도 모른다
             Codex 는 **stderr** 로 답한다. stdout 만 읽으면 «로그인 안 됨» 이 된다
auth.file    Antigravity 는 **한 번 틀린 집을 봤다** — 서버를 띄우기만 해도
             생기는 파일이라 «로그인한 적 없어도 되어 있다» 가 됐다
purge        Codex 는 파일과 sqlite 둘에 두는데 ACP 는 파일만 지운다
auth.acp     `agy` CLI 로 로그인해도 세션은 안 붙었다 — 둘이 다른 집을 본다
```

★ **코드에 에이전트 이름을 박지 않는다.** 여기 표가 는다는 것은 **카탈로그가
는다**는 뜻이어야 한다. `agentInstaller.authPlan` 이 본보기다 — 「`auth.status`
가 있으면 물어보고, 없으면 파일만 본다」로만 적혀 있어서, 새 에이전트를 더하면
**코드를 한 글자도 안 고쳐도** 로그인 확인에 저절로 낀다. `tests/installer.mts`
가 **지어낸 에이전트를 넣어** 그걸 고정한다.

★ **OS 도 같이 본다** (P6). `process.platform` 분기는 세 갈래를 다 적고, 안
타는 쪽도 왜 안 타는지 적는다. 못 재는 칸은 **「안 쟀다」고 적는다.**

## 무엇을 적어두나 — `AgentDef.pkg`

```ts
pkg?: {
  spec: string;                    // "@agentclientprotocol/codex-acp@2.1.0"
  bin: string;                     // "codex-acp"
  overrides?: Record<string, string>;  // { "@openai/codex": "0.159.3" }
  exeEnv?: { name: string; bin: string };
}
```

`exeEnv` 가 🔴 **제일 중요하다.** 두 어댑터 다 엔진 바이너리를 **PATH 에서
찾는 문**을 두고 있는데, 기본값이 다르다:

```
Claude   CLAUDE_CODE_EXECUTABLE   기본: 품은 exe
Codex    CODEX_PATH               기본: **"codex" — PATH 에서 찾는다**
```

지금 Codex 가 핀 판으로 도는 건 **npx 가 제 `.bin` 을 PATH 앞에 끼워주기
때문**이다. 우리 자리에서 직접 띄우면 그 도움이 없어져 **사용자의 `codex`
가 걸린다**(이 기계: 0.155.0). 그러니 전환과 동시에 `CODEX_PATH` 를
우리 `.bin` 으로 박아야 한다. **안 하면 조용히 딴 판이 돈다.**

## 화면이 보여줄 단추 — `AgentState`

사용자가 정한 표 그대로다 (2026-10-01). 계산은 `agentInstaller.stateOf`,
검사는 `tests/installer.mts`.

| 상태 | 언제 | 단추 |
|---|---|---|
| `none` | 안 받았다 | **설치하기** |
| `stale` | 핀이 올라갔다 | **업데이트** · <span style="color:#c00">제거</span> |
| `needLogin` | 받았는데 로그인 안 됨 | **로그인** · <span style="color:#c00">제거</span> |
| `ready` | 받았고 로그인됨 | **로그아웃** · **사용량** · <span style="color:#c00">제거</span> |

- **핀이 안 올라갔으면 그대로 둔다** — 맞는 판이 있으면 `npm` 을 아예 안 부른다
- **낡음이 로그인보다 앞선다.** 핀을 올렸는데 낡은 판이 돌면 «모델이 올라간 줄
  알았는데 아니었다» 가 된다(`docs/PIN.md` §A). 다만 `loggedIn` 도 같이
  돌려주므로 화면은 둘 다 보여줄 수 있다
- **제거는 빨간 단추다.** 받아둔 뒤라면 어느 상태에서나 할 수 있다. 저장소에
  이미 `.danger` 꼴이 있다(`fieldset.bot .bot-drop.danger` — 봇 «빼기»).
  지우는 건 **우리 자리**라 남의 것을 건드리지 않는다
- 제거해도 **로그인은 안 날아간다.** 자격은 `~/.codex`·`~/.claude` 에 있고
  거긴 우리 자리가 아니다 — 로그아웃은 따로 있는 단추다

## Node 도 받는다 — **요구 목록을 비우려고**

> 2026-10-07. 사용자: *"노드 20은 이거 깔릴때 같이 깔리게는 못해?"*.
> **CLI 를 안 깔아도 된다고 해놓고 Node 는 깔라고 하는 것**은 앞뒤가 안 맞는다.
> VSCode 를 쓰는 사람이 다 JS 를 쓰는 것도 아니다.

```
<globalStorage>/node/current/        ← v24.21.0 (npm 11.19.0 동봉)
<globalStorage>/node/aio-node.json   ← 무슨 판을 받았나
```

**에이전트 옆이 아니라 따로 둔다.** 에이전트가 아니고 여럿이 같이 쓰므로
`agents/` 안에 두면 «어느 에이전트의 것» 처럼 보이고, 버려진 프로세스를
쓸어담는 `sweepStrays` 도 `agents/` 만 본다.

### 왜 통째로 받나 — npm 만 받는 길을 먼저 재봤다

**VSCode 가 Node 를 품고 있다.** 띄우는 쪽은 실제로 된다 — 재봤다:

```
Code.exe (ELECTRON_RUN_AS_NODE=1)  …/claude-agent-acp/dist/index.js
→ agentInfo: {"name":"…/claude-agent-acp","version":"0.84.0"}
```

그런데 **받는 쪽이 막힌다.** VSCode 는 npm 을 안 품는다. npm 만 따로 받으면
되나 싶었는데:

```
npm 12.x   engines = ^22.22.2 || ^24.15.0 || >=26.0.0   ← VSCode 의 22.21.1 을 거절
npm 11.21  engines = ^20.17.0 || >=22.9.0               ← 된다
```

🔴 **한 패치 차이로 갈린다.** 그 길로 가면 우리가 **VSCode 의 Node 판에
묶인다** — 저쪽이 올리거나 사용자가 옛 VSCode 를 쓰면 설치가 통째로 막히고,
그건 사용자가 손쓸 수 없는 고장이다. 그래서 Node 를 통째로 받아 **핀을 우리가
쥔다.** npm 이 같이 온다.

| | 크기 |
|---|---|
| win-x64 · win-arm64 | 34MB (`.zip`) |
| linux-x64 · linux-arm64 | 29MB (`.tar.gz`) |
| darwin-x64 · darwin-arm64 | 48MB (`.tar.gz`) |

⚠️ **꼴을 `.zip`·`.tar.gz` 로만 고른다.** 리눅스는 `.tar.xz` 가 더 작지만 푸는
데 `xz` 가 필요하고 그건 늘 있지 않다 — 이미 가진 배선(`unzip.ts` ·
`tar -xzf`)으로 끝나는 쪽이 낫다.

### 어떻게 걸리나 — `PATH` 맨 앞

npm 이 만드는 `.bin/<이름>.cmd` 껍데기는 제 옆에 `node.exe` 가 없으면
**`PATH` 의 `node` 로 떨어진다**(껍데기 안을 열어보면 그렇게 적혀 있다).
그래서 경로만 앞에 세우면 **껍데기를 손대지 않고도** 우리 Node 가 걸린다.
받을 때(`realNpm`)와 띄울 때(`withInstalled`) 둘 다 그렇게 한다.

**사용자 기계에 Node 가 있어도 우리 것을 쓴다.** 판이 어긋나서 생기는 일을
아예 없애려는 것이다 — 핀을 박는 까닭과 같다(§F5).

🔴 **못 받으면 막지 않는다.** 그때는 사용자 기계의 Node 로 돌아간다.
여기서 던지면 **원래 되던 사람까지 막는 셈**이다.

⚠️ 받는 것은 **sha256** 으로 맞춰본다 — nodejs.org 가 그걸 준다. 에이전트
쪽(sha512)과 다르다.

## 받은 것은 **돈다** — 치우는 것도 우리 몫이다

> 2026-10-07. 사용자가 짚었다 — *"다른 애들도 이전게 남아있는지 확인해야될듯?
> 이거 쌓이면 안되지"*. 세어보니 이랬다:

```
antigravity  27개  581MB      ← agy_acp_server 20 · localharness_external 6 · agy 1
codex         1개             ← 부모(node)가 살아 있다. 지금 도는 어댑터다
claude        0개
```

까닭은 **F5** 다. 확장 호스트가 죽으면 `dispose` 가 못 돈다. 그래도 Claude·
Codex 는 **stdin 이 닫히면 제가 알아서 끝나는데**, Antigravity 의 파이썬 서버는
**안 끝난다.** 그래서 한쪽만 쌓였다 — 띄운 횟수만큼 그대로.

### 두 가지를 넣었다

| 언제 | 무엇을 | 왜 |
|---|---|---|
| **지울 때** (`killUnder`) | 그 자리에서 나온 것 **전부** | 지울 자리라 살려둘 까닭이 없다 |
| **켤 때** (`sweepStrays`) | **버려진 것만** | 옆 창이 쓰는 것을 죽이면 안 된다 |

🔴 **«우리 자리에서 나왔나» 로 가르면 안 된다.** `globalStorage` 는 **창끼리
나눠 쓴다** — VSCode 창마다 확장 호스트가 따로 뜨고 저마다 에이전트를 띄운다.
우리 자리에서 나온 것을 전부 죽이면 **옆 창이 쓰던 것까지 죽는다.**

그래서 기준은 **«부모가 살아 있느냐»** 다:

```
부모가 살아 있다  →  어느 창이 쥐고 있다. 안 건드린다
부모가 죽었다    →  그 창은 이미 없다. 버려진 것이다
```

자식은 따로 안 고른다 — **뿌리를 나무째** 죽이면 같이 간다(`taskkill /T`).

> 실제로 쓸어봤다: 뿌리 13개를 내리니 27개가 정리되고 **581MB → 204MB**.
> 남은 둘(`agy`·`codex`)은 부모가 살아 있어 **일부러 살렸다.**

⚠️ **지울 때 사람에게 떠넘기지 않는다.** 전엔 «그 CLI 를 끄고 다시 해보세요»
라고 했는데, 사용자: *"제거할때 무시하고 제거는 안되나? kill 때리고 하는 느낌"*.
맞는 말이다 — 지우겠다고 누른 사람에게 시킬 일이 아니다.

가려내는 판단은 `straysIn()` 하나로 떼뒀다. 프로세스 표를 긁는 것은 판마다
다르지만(윈도우는 PowerShell, 그 밖은 `ps`), **무엇을 버려진 것으로 볼지는
한 자리**이고 검사도 거기 붙는다.

## 창이 둘일 때 — **받기는 한 번만** (2026-10-14)

`globalStorage` 를 창끼리 나눠 쓰므로, 두 창이 **같은 에이전트를 동시에
받으면** 한쪽이 `node_modules` 를 갈아엎는 사이 다른 쪽이 그 자리를 읽는다.

```
<에이전트 자리>/.busy   {pid, window, at}
```

받기·지우기 전에 이 파일을 쥔다. 🔴 **쥔 창이 죽었으면 뺏는다** — 안 그러면
한 번 죽은 창이 그 에이전트를 **영영 못 받게** 만든다(방 락과 같은 규칙).
남의 창이 쥐고 있으면 그 자리에서 «옆 창이 받는 중입니다» 라고 말한다.

## 디스크 정리 — **npm 캐시는 우리 것을 쓰고 버린다** (2026-11-19)

> 사용자: *"캐시 정리할 수 있는 기능 넣을 수 있나?"* — 할당량이 있는 리눅스
> 서버에서 저장이 막힌 뒤에 나왔다.

재보니 큰 것은 우리 자리가 아니었다(이 기계):

```
agents/              953MB   우리 것 · 쓰는 중
node/current         102MB   우리 것 · 쓰는 중
npm-cache/_cacache  3.7GB    npm 공용 — `npm install` 이 받을 때마다 한 벌씩 남겼다
npm-cache/_npx      6.6GB    npx 공용 — 우리가 npx 를 쓰던 때와 다른 프로그램의 것
```

**① 더 안 쌓는다.** `install` 은 `npm_config_cache=<root>/npm-cache/<id>` 로
받고 **끝나면(실패해도) 지운다.** 다시 받을 때 몇 초 아끼는 것보다 사용자
디스크가 먼저다.

**② 쌓인 것은 로봇 화면의 «디스크 정리» 에서** (`cleanup.ts`):

| 칸 | 지우나 | |
|---|---|---|
| 받아둔 에이전트 · Node | ❌ | 쓰는 중 — 에이전트는 위의 「제거」 로 |
| 받다·지우다 남은 것 | ✅ 바로 | `agents/*.old-*` · `npm-cache/*` · `node/_node-*` · `node/node-v*` |
| npm 캐시 · npx 캐시 | ✅ **묻고** | 남의 자리 — 지워도 고장 나지 않지만 다른 프로그램이 다시 받는다 |

🔴 **찌꺼기는 한 시간 묵은 것만.** 옆 창이 지금 받고 있는 캐시나 푸는 중인
Node 를 지우면 그 받기가 깨진다. ⚠️ npm 캐시 자리는 **npm 에게 묻는다**
(`npm config get cache`) — `.npmrc` 로 옮겨뒀을 수 있다. 못 물으면 OS 기본값
(윈도우 `%LOCALAPPDATA%\npm-cache`, 그 밖 `~/.npm`). 지우기는 **한 칸씩** 해서
다른 프로그램이 쓰는 칸만 남기고 그 수를 말한다.

## 안 하는 것

- **`--omit=optional`** — 바이너리를 빼고 우리가 대주면 227MB 를 아끼지만,
  플랫폼별 꾸러미를 우리가 골라야 한다. npm 이 `os`/`cpu` 로 알아서 고르는
  일을 손으로 하는 셈이라 **지금은 안 한다.** 한 벌만 받으면 중복은 없다.
- **옛 npx 자리 치우기** — 3.7GB 가 남지만 **남의 자리라 안 건드린다.**
  사용자에게 «여기에 이만큼 있습니다» 라고 알려주는 것까지가 우리 몫이다.

## 되돌리기

`pkg` 를 안 적은 에이전트는 예전처럼 `command`+`args` 로 띄운다.
`aiInOne.agents` 로 사용자가 덮어쓴 것도 그 길로 간다. **전환은 에이전트
단위이고, 한 줄 빼면 돌아간다.**
