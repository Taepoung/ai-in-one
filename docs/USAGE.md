# AI in One 사용법

> **대상 버전: v1.0** — 화면과 동작은 구현된 것을 기준으로 쓰여 있습니다.
>
> 아직 없는 것: 코드 블록 문법 강조·복사 버튼 · 마크다운 표 · 압축 구분선 · 끊긴 턴 보정.

Claude Code, Codex, Gemini CLI를 VSCode 안에서 메신저처럼 씁니다.
기존 구독을 그대로 쓰므로 API 키가 필요 없습니다.

---

## 1. 준비

### 1.1 확장 설치

VSCode 마켓플레이스에서 `AI in One`을 설치합니다.

### 1.2 에이전트 CLI 설치와 로그인

**확장이 CLI를 대신 설치해주지 않습니다.** 쓰려는 에이전트를 직접 설치하고 로그인해야 합니다.
로그인은 각 CLI가 처리하므로 **이 확장은 여러분의 토큰을 다루지 않습니다.**

| 에이전트 | 준비 |
|---|---|
| Claude | 터미널에서 `claude` 를 실행해 설치·로그인 |
| Codex | 터미널에서 `codex` 를 실행해 설치·로그인 |
| Gemini | 터미널에서 `gemini` 를 실행해 설치·로그인 |

하나만 준비해도 됩니다. 준비가 안 된 에이전트는 방 만들기 화면에서 **이유와 함께 안내**가 뜹니다.

> 필요한 것: **Node 20 이상**

## 2. 채팅 열기

셋 중 아무거나:

- **`Ctrl+Shift+A`** (macOS `Cmd+Shift+A`)
- 상태 표시줄의 **`💬 AI`** — 안 읽은 메시지가 있으면 숫자가 붙습니다
- 명령 팔레트 → `AI in One: 채팅 열기`

**앱은 하나만 뜹니다.** 이미 열려 있으면 그 탭이 앞으로 나옵니다.
에디터 오른쪽에 열리므로 **파일 탐색기가 가려지지 않습니다.**

## 3. 화면 세 개

```
[목록]  ─── + ──→  [방 만들기]  ──→  [채팅]
   │                                   ↑
   └────────── 방 누르기 ──────────────┘
                  ←── 뒤로 ───
```

### 3.1 목록

방 한 줄은 두 줄로 고정입니다.

```
💬 리팩터링 논의                          2분  ②
   Claude · Sonnet 5                 …/Project/AI_in_one
```

- 왼쪽 아이콘이 **방 유형** — 1:1 💬, 단체방 👥 (v2.0)
- 제목 아래는 **누구와** — 에이전트와 모델. 일하는 중이면 `답하는 중…`,
  쓰다 만 글이 있으면 `초안: …` 이 대신 나옵니다
- 오른쪽 아래는 **작업 폴더**. 지금 열린 폴더가 아니면 색이 다릅니다
- 마우스를 올리면 오른쪽에 `⋮` 가 나타납니다 — 이름 바꾸기 / 방 나가기

**순서는 늘 같습니다**: 현재 프로젝트의 방이 위로, 그 안에서 최근 활동순.

### 3.2 방 만들기

```
┌──────────────────────────┐
│ 방 제목  [리팩터링 논의 ] │
│                          │
│ ── 봇 ────────────────── │
│ 에이전트  ● Claude       │   ← 고르면 아래가 채워집니다
│ 모델     [Opus 5    ▾]   │
│ ▸ 고급 설정               │   ← 사고 강도 · 속도
│ 역할(선택)[            ]  │
│                          │
│ 작업 디렉터리 [현재 WS  ] │
│        [취소] [만들기]    │
└──────────────────────────┘
```

- **제목**을 비우면 `새 대화 N`이 됩니다. 나중에 바꿀 수 있습니다
- **모델 목록은 미리 받아둡니다** — 에이전트를 고르면 기다림 없이 채워집니다
- **역할**은 첫 메시지 앞에 붙는 지시입니다. *"너는 코드 리뷰어다. 구현하지 말고
  지적만 해라"* 같은 전담 방을 만들 수 있습니다
- **작업 디렉터리는 만든 뒤에 못 바꿉니다.** 이때가 유일한 기회입니다

만들면 **바로 그 방으로 들어갑니다.**

> **권한은 여기서 정하지 않습니다.** 방을 만들 때 정해봐야 쓰면서 바꾸게 되므로,
> 채팅 **입력창 옆 🛡 권한 설정**에서 한 자리로 다룹니다(§7). 처음에는 에이전트
> 기본값으로 시작합니다.

> **«고급 설정»에는 사고 강도와 속도가 있습니다.**
> 에이전트가 `Effort`라 부르든 `Reasoning effort`라 부르든 **사고 강도**로 통일해
> 늘 같은 자리에 보여줍니다.

### 3.3 채팅

```
┌──────────────────────────────┐
│ ←  리팩터링 논의           ⋮ │
│    Claude · ~/proj          │
├──────────────────────────────┤

├──────────────────────────────┤
│  +  🛡 [메시지 입력…]     ▶  │
└──────────────────────────────┘
```

## 4. 대화하기

### 4.1 에이전트가 일하는 동안

입력창 바로 위에 **점 세 개와 함께 지금 뭘 하는지** 뜹니다.

| 표시 | 뜻 |
|---|---|
| `연결 중…` | CLI를 띄우거나 세션에 다시 붙는 중 |
| `생각하는 중…` | 보냈고 첫 응답을 기다리는 중 |
| `답하는 중…` | 응답을 받는 중 |
| `작업하는 중…` | 도구를 쓰는 중 (파일 읽기·수정·명령) |
| `권한을 기다리는 중` | 여러분의 승인을 기다리는 중 |
| `질문에 답을 기다리는 중` | 여러분의 답을 기다리는 중 |

**멈추려면** 그 줄의 `중단` 버튼이나 **`Esc`** 를 누릅니다.

> **답하는 중에도 계속 입력할 수 있습니다.** 보낸 메시지는 쌓였다가 턴이 끝나면
> 한 번에 전달됩니다. 이때 응답에 *"질문 3개에 한 번에 답합니다"* 가 붙습니다.

### 4.2 화면에 뭐가 보이나

**말과 결과는 보이고, 과정은 접힙니다.**

- 에이전트의 답은 **마크다운으로** 그려집니다 — 코드 블록, 목록, 굵게, 링크
- **파일 변경**은 `▸ 파일 3개 변경` 카드로 접혀서 붙습니다 (§5)
- **에이전트가 한 일**은 말 **사이사이**에 놓입니다 — 말하고 → 뭘 하고 →
  다시 말한 순서 그대로입니다

  ```
  먼저 테스트를 봅니다.
    ▸ 활동 2개
        ▸ ⌨ Bash                    19:42
        ▾ ⌨ Bash                    19:43    ← 실패한 건 펼쳐져 있습니다
            npm run build
            error TS2304: …
  통과했습니다.                                19:43
  ```

  묶음을 펼치면 **제목 줄만** 보이고, 보고 싶은 것만 다시 펴서 **실행한 명령과
  그 결과**를 봅니다. `Bash` 라고만 적혀 있으면 `ls` 인지 `rm -rf` 인지 알 수
  없으니까요
- **계획**(계획 모드)은 접지 않고 말풍선 아래에 그대로 보여줍니다 —
  끝난 항목은 취소선, 하는 중인 항목은 강조색
- **사고 과정**은 `▸ 생각` 으로 접혀 있습니다. 눌러야 보입니다
- 권한 승인·거부와 건너뛴 질문은 **회색 한 줄**로 남습니다 — 나중에 무슨 일이
  있었는지 볼 수 있어야 하니까요
- 말풍선 옆에 **시각**, 날이 바뀌면 `오늘`/`어제` **구분선**이 그어집니다

### 4.3 목록으로 나가도 계속 돕니다

`←`로 목록에 나가도 **에이전트는 계속 일합니다.** 다른 방을 보거나 코드를 보다가
돌아오면 결과가 쌓여 있습니다. 목록에도 `답하는 중…`으로 표시되고, 끝나면
**안 읽음 배지**가 붙습니다. 방을 열면 `여기서부터 안 읽음` 구분선으로 갑니다.

### 4.4 안 보내진 메시지

보내는 도중에 VSCode가 닫히거나 에이전트가 죽으면, 그 말풍선에 **빨간 테두리와
`다시 보내기`** 가 붙습니다. 누르면 **새 말풍선을 만들지 않고** 그대로 다시 보냅니다.

## 5. 코드 다루기

### 5.1 편집 중인 내용을 그대로 봅니다

**저장하지 않은 파일도 에이전트가 봅니다.** 고치다 만 코드를 그대로 물어볼 수 있습니다.

### 5.2 변경 확인은 2단계

```
1단계   ▸ 파일 3개 변경                      ← 접혀 있음. 눌러서 펼침
          ~ src/core/store.ts   +12 −4
2단계   파일을 누르면 네이티브 diff 탭        ← 제대로 보기
```

**변경 전/후 전문을 따로 보관**하므로, 그 뒤에 파일이 더 바뀌어도 **당시의 변경을
그대로** 볼 수 있습니다. 디스크에 임시 파일을 만들지 않습니다.

읽기만 한 파일은 diff 없이 그냥 열립니다.

### 5.3 `src/foo.ts:42` 는 눌러서 갑니다

대화 속의 `파일:줄` 표기는 링크가 됩니다. 누르면 그 줄로 커서가 갑니다.

### 5.4 되돌리려면 git을 씁니다

되돌리기 기능은 **일부러 만들지 않았습니다.** VSCode의 Source Control에서 변경을
확인하고 `Discard Changes` 하면 됩니다 — 어설픈 자체 되돌리기보다 안전합니다.

## 6. 파일·이미지 붙이기

| 방법 | 쓰는 때 |
|---|---|
| **`Ctrl+V`** | 스크린샷. 가장 많이 쓰게 됩니다 — 에러 화면, UI 시안 |
| **끌어다 놓기** | 탐색기나 바탕화면에서 채팅으로 |
| **입력창 왼쪽 `+`** | 파일 선택 창 |
| **코드 선택 후 우클릭 → `AI in One에 보내기`** (`Ctrl+Shift+S`) | 고른 범위만 |

> **워크스페이스 안의 파일은 내용을 싣지 않고 경로만 보냅니다.** 에이전트가 직접
> 읽으므로 **저장하지 않은 편집 내용까지 반영**되고, 토큰도 아낍니다.
>
> 그래서 워크스페이스 안 파일은 **굳이 붙이지 않아도 됩니다** — `store.ts 봐줘`
> 라고 써도 에이전트가 찾아 읽습니다. 붙이는 건 *어느 파일인지 못 박고 싶을 때*입니다.
>
> 이미지는 경로로는 못 보므로 항상 내용을 싣습니다. 보내기 전에 긴 변이
> **1568px**가 되도록 줄입니다 — 4K 스크린샷을 그대로 보내면 토큰이 폭발합니다.

- 붙인 파일은 입력창 위에 **칩**으로 쌓입니다. `×`로 뺄 수 있습니다
- **첨부만 보내도 됩니다** (글 없이)
- 한 개당 **2MB**를 넘으면 거절하고 이유를 알려줍니다
- 에이전트가 못 받는 형식은 **보내기 전에** 알려줍니다 — 보내놓고 기다리게 하지 않습니다
- 보낸 뒤: 이미지는 썸네일(눌러서 확대), 그 밖에는 칩(눌러서 앞부분 미리보기)

## 7. 권한과 자동화

### 7.1 권한 설정 🛡

입력창 옆 방패 버튼입니다. 누르면 **아래에서 설정이 올라옵니다**:

```
🛡 권한 설정                              ✕
────────────────────────────────────────
● Claude
   권한 모드   [Manual              ▾]
               Always ask before making changes
   승인 주체   [사용자              ▾]
               방에 다른 봇이 있으면 그 봇에게 맡길 수 있습니다
   질문        [물어봄              ▾]
               에이전트가 갈림길에서 물어볼 때
```

**봇마다 따로** 갑니다 — 단체방에서는 봇이 여럿 나열됩니다.

| | |
|---|---|
| **권한 모드** | 무엇을 물어볼지. **에이전트가 주는 목록 그대로**입니다 |
| **승인 주체** | 물어볼 때 누구에게. 지금은 사용자뿐입니다 |
| **질문** | 에이전트가 갈림길에서 물을 때 답할지, 알아서 판단하게 할지 |

고르면 **그 자리에서 세션에 적용**됩니다. 방을 만들 때 정하지 않고 여기서 다루는
이유는, 쓰다 보면 바꾸게 되기 때문입니다 — 리뷰만 시키다가 고치게 하는 일이 흔합니다.

> `⋮` 메뉴에 숨기지 않은 이유가 있습니다 — **켜둔 걸 잊으면 파일이 마음대로
> 바뀝니다.** 입력창 옆이면 보낼 때마다 눈에 들어옵니다.

### 7.2 권한 모드

목록과 설명은 **에이전트가 주는 그대로**입니다. Claude Code는 `Manual ·
Accept edits · Plan · Auto · Bypass permissions`, Codex는 `Ask for approval ·
Approve for me · Full access` 처럼 이름도 개수도 다릅니다.

우리가 다시 쓰지 않는 이유는, 그러면 **에이전트가 바뀔 때 틀린 설명이 남기**
때문입니다. 고른 값의 설명이 밑에 따라 붙으니 그걸 보고 고르면 됩니다.

> ⚠️ **에이전트가 스스로 승인하는 모드도 있습니다.** 그때는 승인 카드가 뜨지
> 않습니다 — 예를 들어 **Codex의 기본값은 «Approve for me»** 로, 위험해 보이는
> 것만 물어봅니다.
>
> 물어보지 않고 넘어간 것도 **`▸ 활동 N개`에 남습니다**(§4.2) — 무슨 명령이
> 돌았는지는 언제나 볼 수 있습니다.

### 7.3 승인 카드

에이전트가 물어보면 **대화 안에 카드로** 뜨고, **무엇을 승인하는지 그 자리에서
보여줍니다**:

```
🖥 터미널 명령
   rm -rf build && npm run build
                        [허용] [거부]

✎ 파일 수정
   src/core/store.ts            ← 눌러서 열 수 있습니다
   ▸ 바뀔 내용 보기
                        [허용] [거부]
```

**결정은 대화에 기록됩니다** — `✓ 파일 읽기 — 허용` 처럼 회색 한 줄로 남습니다.
조용히 지나가면 나중에 무슨 일이 있었는지 알 수 없습니다.

### 7.4 에이전트의 질문

에이전트가 갈림길에서 물어보면 대화 안에 **폼 카드**가 뜹니다. 답하거나
`건너뛰기`를 누르면 에이전트가 알아서 판단합니다.

`질문`을 **알아서 판단**으로 두면 묻지 않고 스스로 정합니다. 건너뛴 질문도
기록에 남습니다 — 나중에 *"아 이걸 물었었구나"* 를 볼 수 있어야 하니까요.

## 8. 모델 바꾸기

`⋮` 메뉴에 현재 에이전트의 모델 목록이 있습니다. 고르면 **그 자리에서 바뀌고**
타임라인에 *"모델이 … 로 바뀌었습니다"* 가 남습니다 — 나중에 왜 응답 성향이
달라졌는지 알 수 있어야 하니까요.

고른 모델은 **에이전트별로 기억**되어 다음 방의 기본값이 됩니다.

## 9. 대화가 길어지면

컨텍스트가 **90%를 넘으면** 대화 아래에 `대화 압축하기` 배너가 뜹니다.
`⋮ → 대화 압축하기` 로도 언제든 할 수 있습니다.

누르면 에이전트가 지금까지의 대화를 요약으로 압축합니다. 방에 설정한 **역할은
압축 후 다시 주입**되므로 다시 말해줄 필요가 없습니다.

압축이 끝나면 대화에 선이 하나 그어집니다:

```
──── 여기까지 압축됨 — 위쪽은 에이전트가 요약으로 기억합니다 ────
```

**에이전트가 스스로 압축하기도 합니다.** 컨텍스트가 차면 알아서 줄이는데,
그때도 같은 선이 그어집니다 — 선이 없으면 *«아까 말한 거»* 가 왜 안 통하는지
알 길이 없으니까요. **요약 내용 자체는 보여주지 않습니다.** 읽을 것은 자기
대화지 요약이 아닙니다.

> 압축을 지원하지 않는 에이전트에서는 메뉴에 나타나지 않습니다.

> **토큰·비용은 보여주지 않습니다.** 채팅은 대화를 읽는 곳이고, 숫자를 알아도
> 할 일이 달라지지 않습니다. 필요하면 각 CLI의 `/usage` 로 확인하세요.

## 10. 세션이 끊겼을 때

VSCode를 껐다 켜면 **에이전트 프로세스가 죽습니다.** 방을 열면 원래 세션에 다시
붙는데, 그러면 대화 텍스트뿐 아니라 **에이전트가 세운 계획·읽은 파일 기억까지**
그대로 살아납니다. 대부분은 이렇게 조용히 이어집니다.

못 붙으면 이렇게 물어봅니다:

```
⚠ 이전 세션이 끊겨 에이전트는 위 대화를 모릅니다.
  지금까지의 대화(메시지 84개 · 약 32,000자)를 다음 메시지에 함께 보낼까요?
  최근 것은 그대로, 오래된 긴 메시지는 가운데를 줄여서 보냅니다.

        [다시 시도]   [대화 넘겨서 시작]   [기록만 두고 시작]
```

| 고르면 | 무슨 일이 |
|---|---|
| **다시 시도** | 원래 세션에 **한 번 더** 붙어봅니다. 되면 계획·메모리까지 돌아옵니다 |
| **대화 넘겨서 시작** | 새 세션에 지금까지의 대화를 글로 넣습니다. **토큰이 듭니다** |
| **기록만 두고 시작** | 새 대화처럼 갑니다. 화면의 기록은 그대로 남습니다 |

뒤의 둘은 **어차피 새 세션**입니다 — 차이는 대화를 넘기느냐뿐입니다.
«대화 넘겨서 시작»을 골라도 그 자리에서는 아무 일도 안 일어나고,
**다음 메시지에 함께** 실려 갑니다(턴을 따로 쓰지 않으려고요).

> 이전 세션이 컨텍스트를 많이 쓰고 있었으면 배너가 그 비율도 알려줍니다 —
> 다시 넣으면 곧 압축이 필요할 수 있다는 뜻입니다.

**왜 못 붙나** — 세션은 에이전트 CLI가 자기 디스크에 보관하고, **첫 메시지를
받아야 기록합니다.** 그래서 방을 만들고 아무 말도 안 한 세션은 되살릴 수
없습니다. 방 정보(`⋮ → 방 정보`)에 **세션 id**가 있고, 아직 대화 전이면
그렇다고 적혀 있습니다. id는 눌러서 복사할 수 있어 터미널에서
`claude --resume <id>` 로 직접 확인할 수도 있습니다.

## 11. 방 관리

| 하고 싶은 것 | 방법 |
|---|---|
| 이름 바꾸기 | 목록에서 방에 마우스를 올리면 나오는 `⋮` → `이름 바꾸기` (또는 `F2`), 채팅 `⋮ → 이름 바꾸기` |
| 방 정보 보기 | 채팅 `⋮ → 방 정보` — 디렉터리·모델·사용량·역할 |
| 역할 고치기 | 방 정보 안에서. 고치면 **다음 프롬프트부터** 반영됩니다 |
| 방 나가기 | 목록 `⋮ → 방 나가기`, 또는 채팅 `⋮ → 방 나가기` |
| 대화 찾기 | 목록 상단 검색창 |
| 방 안에서 찾기 | 채팅에서 `Ctrl+F` |

> **`←`(뒤로)와 `나가기`는 다릅니다.** 뒤로는 목록으로 돌아갈 뿐이고,
> **나가기는 방과 에이전트 쪽 세션을 함께 지웁니다. 되돌릴 수 없습니다.**

### 대화 찾기

목록 위 검색창 하나로 **방 이름과 대화 내용을 함께** 찾습니다.

```
┌──────────────────────────────┐
│ 🔍 방 이름·대화 내용 찾기   ▣ │   ▣ = 이 프로젝트 방만 보기
└──────────────────────────────┘
   방 2개
   · 리팩터링 논의
   대화 5건
   · 리팩터링 논의   …LRU 캐시를 쓰면…
```

방 이름은 **즉시** 걸러지고, 대화 내용은 잠깐 뒤에 결과가 붙습니다.
결과를 누르면 **그 방의 그 메시지로 건너뛰고** 잠깐 표시됩니다.

### 다른 프로젝트의 방

방은 워크스페이스와 무관하게 저장되므로, 다른 프로젝트에서 만든 방도 목록에 보입니다.
**숨기지 않습니다** — 어제 하던 걸 이어서 볼 때가 있으니까요. 대신:

- 현재 프로젝트의 방이 **위로** 옵니다
- 그 밖의 방은 둘째 줄에 `다른 프로젝트 ·` 가 붙습니다
- 열면 맨 위에 **배너**로 알려줍니다
- 검색창 오른쪽 **필터 아이콘**을 누르면 현재 프로젝트 것만 보입니다

## 12. 잘 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 방 만들기에서 모델 목록이 안 뜸 | 아래에 뜬 이유를 보세요. 대개 **CLI 미설치 또는 미로그인**입니다 |
| `로그인이 필요합니다` | 터미널에서 그 CLI를 직접 실행해 로그인하세요 |
| 첫 방이 유난히 느림 | `npx`가 CLI를 처음 내려받는 중입니다. *"처음 시작하는 중입니다"* 가 뜹니다 |
| 응답이 없음 | 출력 패널 → `AI in One` 채널의 로그 |
| *"프로세스가 종료되어 답변이 끊겼습니다"* | **다시 보내면 이어서 합니다.** 세션에 자동으로 재접속합니다 |
| 첨부가 거절됨 | 2MB를 넘었거나, 그 에이전트가 받지 못하는 형식입니다 (이유가 함께 뜹니다) |
| 응답이 중간에 잘림 | 받는 도중에 VSCode가 닫힌 경우입니다. **에이전트는 전체를 기억하므로** 이어서 물어보면 됩니다 |
| *"권한 모드가 … 라 승인을 물어보지 않을 수 있습니다"* | 그 에이전트의 권한 모드를 우리가 알아보지 못했습니다. AI in One의 권한 설정이 적용되지 않습니다 |

문제가 계속되면 `AI in One` 출력 채널의 로그를 첨부해 이슈를 남겨주세요.

## 대화는 어디에 남나

```
globalStorage/
├─ rooms.json        방 목록
├─ app.json          에이전트별 마지막 모델
├─ rooms/<id>.jsonl  대화 (한 줄씩 덧붙임)
└─ blobs/<sha256>    첨부 원본 · 변경 전후 내용
```

VSCode를 껐다 켜도, 확장을 닫았다 열어도 **방·대화·안 읽음·초안이 그대로** 남습니다.
에이전트 쪽 세션에도 다시 붙으므로 어제 하던 이야기를 이어서 할 수 있습니다.
