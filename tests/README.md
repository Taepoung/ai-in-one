## 왜 여기 있나

**2026-09-28 까지 이 파일들은 임시 폴더에만 있었다.** git 에도 백업에도 없었고,
어느 시점엔가 **46 개가 소리 없이 사라졌다** — `leave.mts` · `forkblob.mts` ·
`queueui.mts` 를 포함해서. 스위트가 82 → 83 → 84 로 **늘기만 하는 것을 보느라
아래에서 빠지는 것을 못 봤다.**

옮기자마자 **제품 버그 하나가 바로 튀어나왔다.** 저장소 경로에는 공백이 있는데
(«Taein Yoon»), 임시 폴더에는 없었다 — 그래서 `shell: true` 로 띄울 때 경로가
쪼개지는 문제를 여태 아무도 못 봤다. 스무 개가 한꺼번에 터졌다.
검사가 실제 코드와 **같은 땅**에 살아야 하는 이유다.

## 가짜 에이전트에게 시키는 법

프롬프트에 **표식**을 끼워 넣으면 그 소식을 흘린다. 환경변수는 세션 내내 걸리는
조건(`AIO_FAKE_*`), 표식은 **한 턴짜리**다.

```
[[diff:경로]]    파일을 고친 척한다        [[fail:경로]]   막힌 수정
[[ask:제목]]     턴 중간에 승인을 묻는다    [[bg:id]]       백그라운드로 띄운 척
[[wake:ms]]      턴이 끝난 뒤 스스로 말한다
[[plan]]         계획 (항목형, 안정판)     [[planmd]]      계획 (마크다운)
[[planitems]]    계획 갱신 (항목형)        [[planfile]]    계획이 파일에 있다
[[planrm]]       계획을 거둔다
[[weird]]        **우리가 모르는 종류**     [[mode:…]]      에이전트가 모드를 바꿨다
[[cfg:모델]]     우리가 안 시킨 설정 변경   [[info:제목]]   session_info_update
```

> 🔴 **안 보내는 소식은 못 재는 소식이다** (2026-10-09). 계획·모드·설정이
> `translate()` 에서 통째로 버려지고 있었는데 **검사 64개가 전부 조용했다** —
> 없어서가 아니라 **여기가 그 소식을 안 보내서**였다. 새 길을 낼 때는
> **보내는 쪽부터** 고친다.

## `probes/` 는 왜 빠져 있나

**진짜 CLI 를 띄우는 것들**이다. 로그인과 할당량이 필요하고, 한 번에 몇 분씩
걸리며, 돌릴 때마다 **결과가 달라질 수 있다**(모델이 답하는 것을 재므로).
자동 검사에 섞으면 «내 코드가 깨졌나 쿼터가 떨어졌나»를 못 가린다.

손으로 돌린다:

```
node tests/probes/delsess2.cjs     # 세션을 지우면 디스크에서 뭐가 사라지나 (Claude)
node tests/probes/agymethods.cjs   # Antigravity 가 할 줄 아는 메서드 (프롬프트 안 씀)
node tests/probes/agydelete.cjs    # Antigravity 는 지우면 지워지나
node tests/probes/newsess.cjs      # 메시지마다 세션이 새로 생기나
node tests/probes/fsseam.cjs       # 파일 접근이 우리를 거치나
npx tsx tests/probes/agysay.mts    # ★ Antigravity 가 say·check_queue 를 제대로 쓰나
```

★ **`agysay.mts` 는 다른 것들과 생김새가 다르다** — ACP 를 손으로 말하지 않고
**제품 코드를 그대로 띄운다**(`RoomManager` · `McpServer` · 진짜 바이너리).
그래서 재는 것이 «저쪽이 이 메서드를 아나»가 아니라 **«우리가 지은 것이 저쪽에서
도나»** 다. 상대 봇은 가짜라 할당량은 한쪽만 든다.

여기서 나온 실측은 **`docs/ROADMAP.md` 에 옮겨 적는다.** 프로브 자체가 답이
아니라, 프로브가 한 번 재고 로드맵이 그걸 기억한다.

## 검사를 쓸 때

- **한 줄짜리 «통과»를 만들지 않는다.** 단언문에 «왜 이게 맞는가»를 적는다 —
  나중에 깨졌을 때 읽을 사람이 그 줄만 본다.
- **개수만 세지 않는다.** `close` 와 `delete` 처럼 **겉보기가 같고 결과가 다른**
  것들이 있다. 「몇 번 불렀나」가 아니라 「어느 쪽으로 불렀나」를 잰다.
- **전제부터 확인한다.** 취소가 안 꽂혔거나 도구가 안 돌았으면 그 판은
  **아무것도 안 잰 것**이다. 결론보다 먼저 찍는다.
- **고정값을 실제와 다른 모양으로 만들지 않는다.** `room.messages.push(…)` 로
  밀어 넣을 때 `deliveredTo` 를 비우거나 빠뜨리기 쉬운데, **실제 경로는 절대
  그런 줄을 안 만든다.** 아무도 그 칸을 안 읽는 동안은 티가 안 나다가, 읽는
  코드가 생기는 날 **엉뚱한 데서** 터진다 — 2026-10-09 에 `model.mts` 와
  `carry.mts` 가 그랬다.
- **시간을 믿지 말고 그 상태를 기다린다.** «300ms 면 저쪽이 바빠졌겠지» 는
  스위트 예순 개 뒤에서 깨진다. 깨진 자리는 재려던 것이 아니라 **전제**라서,
  읽는 사람이 엉뚱한 곳을 판다.
- **기다릴 신호는 재려는 것과 같은 자리에서 나와야 한다.** «말풍선이 떴다»로
  기다리고 «프롬프트가 나갔나»를 쟀더니, 둘 사이에 틈이 있어서 느린 기계에서만
  깨졌다 — `sendCompose` 는 메시지를 적고 저장한 **다음에** 보낸다.
- **전제가 안 서면 «실패»가 아니라 «전제가 안 섰다»로 터뜨린다.** 그래야 다음에
  읽는 사람이 **재려던 것이 깨진 건지 전제가 안 선 건지**를 안 헷갈린다.
- `.mts` 는 끝에 **`mgr.dispose()`** — 안 놓으면 가짜 에이전트가 이벤트 루프를
  붙잡아 «통과»를 찍고도 프로세스가 안 끝난다. 스위트에서는 5 분 타임아웃을
  먹고 실패로 찍힌다.
